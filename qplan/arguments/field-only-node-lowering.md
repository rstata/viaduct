# Argument for [field-only-node-lowering]

This claim concerns the pre-reasoning translation performed by `TestWorld`, not production GraphQL schema rewriting and not a claim that Viaduct's public node-resolver API has disappeared. The supported source domain contains ordinary GraphQL SDL and fragments, field resolver functions, and raw node lookup functions. A lowered node-valued field must be declared as `Node` or a subtype, every possible concrete output type must have a raw node lookup, and outputs that mix node-resolved and inline object values are excluded.

For each Node subtype `T` actually used as a source field's named output type, schema decoding adds one concrete internal type `T$Bridge { $id: ID, $node: T }`. These bridge types have no generated type hierarchy. For each source field `foo(args): W<T>`, where `W` is its complete list and nullability wrapper, decoding adds `foo$bridge(args): W<T$Bridge>`. When `foo` has a source field resolver, that producer is moved to `foo$bridge` and its raw node-reference output is mapped pointwise to bridge objects containing typed IDs; passive nested node references are rewritten in the same way.

Arguments occur only at `foo$bridge`. Consequently `foo(a)` and `foo(b)` lower to distinct `foo$bridge(a)` and `foo$bridge(b)` keys without argument transfer to `$node`, which is argumentless. Null, error, and list structure are mapped recursively without changing their positions or list/nullability declarations.

Each synthetic ID encodes the concrete object type together with the raw ID. The generated resolver at `T$Bridge.$node` has fixed object fragment `{ $id }`; it decodes the type, checks that it is a possible type of `T`, invokes the corresponding raw node lookup, checks that the returned object repeats the input ID, and recursively lowers nested node-valued fields. For abstract `T` and lists containing mixed concrete types, dispatch therefore occurs independently at each bridge-object occurrence.

Synthetic definitions are absent from source GraphQL text. Fixture parsing lowers `foo(args) { selections }` to `foo$bridge(args) { $node { selections } }`, and resolver fragments, provider paths, raw outputs, and operation selections cross the same compiler boundary. Thus source obligations correspond to a producer application at `foo$bridge(args)` followed by one `$node` application at every non-null bridge-object occurrence. In a list, ordinary OER traversal supplies each element's list-indexed occurrence identity rather than hiding all raw node lookups inside one list-valued loader application.

The implementation tests provide finite evidence for argument preservation, concrete and abstract bridge generation, per-element list dispatch, nested lowering, null/error/list mapping, registry edges, and correctness under Resolver01 through Resolver03. They are not a machine-checked proof. Mixed node/inline abstract outputs, malformed raw node references, missing node lookups, and directives are outside this claim.
