# Argument for [field-only-node-lowering]

This claim concerns the pre-reasoning translation performed by `TestWorld`, not production GraphQL schema rewriting and not a claim that Viaduct's public node-resolver API has disappeared. The supported source domain contains ordinary GraphQL SDL and fragments, field resolver functions, and raw node lookup functions. A lowered node-valued field must be declared as `Node` or a subtype, every possible concrete output type must have a raw node lookup, and outputs that mix node-resolved and inline object values are excluded.

For each source field `foo(args)` whose declared output is in that domain, schema decoding adds an internal bridge: `foo$id(args)` for a singular node output and `foo$ids(args)` whenever the output has one or more list layers. Its type expression replaces each named node output with `ID` while preserving the complete list and nullability structure; list rank is represented by that type rather than repeated plural suffixes. When `foo` has a source field resolver, that producer is moved to the bridge and its raw node-reference output is mapped pointwise to typed IDs; passive nested `foo` values are rewritten to the same bridge coordinate in their containing resolver's output. The generated resolver at `foo` requires the exact sibling bridge key and maps those typed IDs pointwise through the corresponding raw node lookup.

Arguments remain on both coordinates. Consequently two singular source occurrences `foo(a)` and `foo(b)` become the distinct bridge and loader pairs `foo$id(a)` with `foo(a)`, and `foo$id(b)` with `foo(b)`; list-shaped occurrences use `foo$ids(a)` and `foo$ids(b)`. Lowering therefore does not merge unequal `Value.Key` argument tuples. Null, error, and list structure are mapped recursively without changing their positions or list/nullability declarations.

Each synthetic ID encodes the concrete object type together with the raw ID. This preserves the runtime dispatch information carried by a source node reference even when `foo` is declared as the abstract `Node` interface or returns lists containing different concrete node types. Applying the generated loader decodes that type, checks that it is a possible type of the source field, invokes the corresponding raw node lookup, checks that the returned object repeats the input ID, and then recursively lowers any nested node-valued fields.

GraphQL-visible selections remain selections of `foo`; synthetic bridges are not parsed from source text. Resolver demand is translated so demand beneath a source node field is projected against the loaded object while the generated loader's argument-dependent object fragment introduces the matching bridge as an internal requirement. Thus source obligations and lowered obligations correspond as `foo(args)` producing one or more node references followed by node lookup versus `foo$id(args)` or `foo$ids(args)` producing typed IDs followed by the generated field resolver at `foo(args)`. These remain separate canonical resolver applications: lowering never normalizes the bridge producer back onto the `foo` loader coordinate.

The implementation tests provide finite evidence for argument preservation, abstract per-element list dispatch, nested lowering, null/error/list mapping, registry edges, and correctness under Resolver01 through Resolver04. They are not a machine-checked proof. Mixed node/inline abstract outputs, malformed raw node references, missing node lookups, and directives are outside this claim.
