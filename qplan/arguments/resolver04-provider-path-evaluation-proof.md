# Argument for [resolver04-provider-path-evaluation-proof]

`semantics/Variables.kt` reads a validated provider after its root field cell has been selected. A nonterminal null or error returns immediately, an object advances through the one applicable child selection, and validation excludes traversal through lists or simple values. At the terminal position, null, error, and simple values are already inputs, while a list is converted positionally and may contain nested lists but not objects.

`tla/ProviderPathEvaluation.tla` represents the remaining exact keys and encountered values as one finite trace per binding. Every nonterminal trace step either preserves a null/error value or reads the exact key from an object value; the final trace value must be convertible. Terminal list conversion is represented by finite element sequences and a strictly decreasing rank for nested lists, avoiding unsupported `RECURSIVE` operators. `ProviderPathEvaluationProof.tla` proves exact trace shape, each traversal branch, null/error absorption for every remaining suffix position, input-valued completion, position-preserving list conversion, and finite rank.

`tla/ProviderReads.tla` instantiates this structural model at the actual immutable provider-root cell and constrains the provider-read function at that root value to equal the structural path result. The existing prefix/final cell identity then proves the stored binding agrees with the final correctness judgment. The remaining refinement assumption is that Kotlin selections, cells, value variants, exact keys, and list elements induce these finite carriers and trace equations. `ProviderPathEvaluationMC` checks direct, nested-object, early-null, and nested-list examples; `ProviderReadsMC` and `Resolver04ApplicationMC` check the connection to the occurrence fold and final result.
